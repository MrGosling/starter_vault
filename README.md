# Заготовка хранилища

Скопируйте папку к себе и откройте её в Obsidian через «Open folder as vault». Настройки агента лежат выключенными в папке `оснастка/`, а порядок включения описан в её `README.md`.

## Что где лежит

| Файл или папка        | Что там держат                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| [[Справка о системе]] | Опишите здесь свою систему: стадии, имена полей, раздел «Что неясно». Это главный файл хранилища.                                                    |
| [[Стек и окружение]]  | Назовите платформу, версии и рамки, в которых пишете код. Подавайте его модели вместе со справкой перед задачами на код.                             |
| [[Решения]]           | Держите по записи на каждое решение: развилка, выбранный вариант, цена выбора.                                                                       |
| [[Промпты]]           | Храните рабочие копии промптов воркшопа: секретарь, аналитик, карта компромиссов.                                                                    |
| `inbox/`              | Складывайте сюда сырьё: протоколы планёрок, куски переписки, черновые заметки. Разбирайте, когда дойдут руки - за неделю в папке ничего не портится. |
| `clippings/`          | Веб-клипер кладёт сюда снимки задач из бэклога и статьи.                                                                                             |
| `effort/`             | Заводите папку на тему или на задачу и держите в ней рабочие документы: постановку, заметки по ходу, ссылки на решения.                              |

## Схема со слайда в этих папках

Хранилище повторяет схему из части 2 в свёрнутом виде. Исходник кладут в `inbox` или `clippings` и больше не правят. Пока документ по теме меняется, он живёт в `effort/`. Выясненное переезжает в «Справка о системе.md», «Решения.md» и «Стек и окружение.md», откуда его берёт модель. Указатель и журнал из схемы появляются позже, когда справка делится на несколько файлов.

## Четыре правила хранилища

1. Начинайте справку одним файлом, а делите её тогда, когда перестаёте дочитывать до конца за один заход или когда модель начинает путаться в середине. Разбивайте по зонам (стадии, интеграции, роли), связывайте страницы ссылками вида `[[Имя страницы]]` и держите указатель со строкой на страницу, первым файлом папки. Карта связей по Ctrl+G показывает структуру хранилища и заметки, на которые никто не ссылается. Два её режима описаны в файле «Obsidian - полезный минимум.md» из общей папки.
2. Обновляйте справку в том же чате, где шёл разговор. Просите дословно: «обнови справку: что нового мы выяснили», а потом просмотрите правку и примите её.
3. Снимок из бэклога нужен только на время разового вопроса. Перенесите в справку правило, которое вывели в разговоре, а снимок удалите.
4. Запрет на чтение секретов ставьте правилом, а не памяткой. Границы выноса наружу задаёт внутренний регламент банка. Техническую меру внутри хранилища держат строки `Read(./.env)` и `Read(./secrets/**)` в блоке `permissions.deny` файла `.claude/settings.json`: правила разрешений исполняет клиент, а не модель, поэтому запрет словами в промпте остаётся просьбой. Почему в этих путях стоит `./`, а не ведущий слэш, написано в `оснастка/README.md`.

## С чего начать

1. Заполните [[Справка о системе]]. Писать можно грязно, а можно попросить ИИ собрать первую версию из пары ваших заметок и протокола.
2. Поправьте в [[Стек и окружение]] версию платформы и имена.
3. Остальное наполняйте по ходу работы.
4. Когда справку придётся прикладывать к каждой задаче на код, перенесите её в репозиторий приложения файлом `AGENTS.md`, а рядом положите `CLAUDE.md` из одной строки `@AGENTS.md`. Codex, Copilot, Cursor и Claude Code читают тогда один текст. Claude Code не открывает `AGENTS.md` сам, поэтому строка-ссылка обязательна. Команда `/init` собирает первую версию. Держите файл короче 200 строк. Команда `/context` в разделе Memory files показывает, что загрузилось, а `/doctor` предлагает вырезать то, что модель и так прочитает в коде.
