# Стек и окружение

> Этот файл подаём модели вместе со справкой перед любой задачей на код.

Платформа - Frappe Framework v16
Каждый DocType описываем JSON-метаданными: поля, типы, связи.
Server Script Frappe выполняет как Python в песочнице, где доступно
только разрешённое API frappe.* (get_doc, get_all, frappe.utils...),
а импорт модулей не работает.
Отчёты бывают двух видов: Query Report на SQL и Script Report на Python.
Клиентскую логику пишем в Client Script. Форму Frappe рисует из
метаданных, поэтому в тестах ищем поля по атрибуту [data-fieldname]:
input[name] на такой форме не находится.

О чём просим модель, когда она пишет код:

- Не уверен в методе или хуке - ставь TODO с комментарием, а не выдумывай.
- Имена полей бери из справки о системе, отсутствующие помечай «уточнить».
- Зарезервированные имена name, owner и creation не занимай.
- Скрипт на хуке сохранения (before_save и подобных) предлагай
  с оговоркой: ошибка в нём ломает сохранение всех документов типа.
- Называй слой изменения: код в приложении или `Custom Field`
  и `Property Setter`. Не назвав слой, оставляем выбор модели,
  а эти два решения по-разному переживают обновление и по-разному
  переносятся между стендами.
- К данным ходи через `frappe.db` и `frappe.qb`. Прямой SQL -
  только там, где ORM не покрывает, и с комментарием почему.
